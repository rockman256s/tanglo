# Генератор уровней WAZE

Офлайн-генератор уровней для игры со стрелками. Уровни собираются заранее в паки (как в референсе:
у всех игроков одинаковые) и проверяются кодом самой игры (`../src/level.js`).

Зависимостей нет, нужен Node 18+.

```sh
npm run build                         # 1…20000 → levels/ (≈2 ч на 12 ядрах; прерванная сборка продолжается)
node tools/build.js --from 1 --to 500 # любой диапазон
npm run check                         # каждый уровень через WG.level.validate игры + сводка метрик
npm run view                          # http://localhost:8080/tools/viewer.html — листать и проходить уровни
node tools/one.js 150 out.json        # один уровень с метриками
```

## Формат

`levels/index.json` — `{ format, packSize, count, packs: [...] }`.
`levels/pack-0000.json` — `{ format, from, to, levels: [строка, …] }`, по 100 уровней в паке.

Строку уровня читает `src/codec.js` (работает и в Node, и в браузере как `WG.levelCodec`):

```js
const level = WG.levelCodec.decode(pack.levels[n - pack.from], n);
// → { id, w, h, mask, arrows: [{ id, cells: [[x, y], …], color }], kind, picture? }
new WG.level.Board(level); // формат совпадает с моделью игры
```

- `cells` — от хвоста к голове, направление головы — последний отрезок.
- `color` — индекс в палитре темы (0…7).
- `mask` — `null` или строки из `#`/`.` (как в `shapes.js` игры). Лучи проходят дыры маски насквозь.
- `kind` — `chaos` или `picture`; у картинок `picture = { kind: 'fill' | 'mask' | 'contour', name }`.

## Как это устроено

1. **Профиль** (`src/profile.js`) — по номеру уровня: сложность `d`, размер поля, раскладка потока,
   распределение длин, цели отбора. Каждый 5-й уровень — передышка, каждый 10-й — бонус-картинка.
2. **Обратное построение** (`src/construct.js`). Стрелки ставятся в порядке, обратном снятию: луч новой
   стрелки должен быть пуст, тело может лечь на чужие лучи. Поэтому каждый уровень решаем по построению.
   Выбор каждой стрелки учитывает поток, фронт заполнения, закрытие ещё не заблокированных лучей и штраф
   за клетки, которые останутся без выхода (так покрытие держится на уровне ≈98,5%).
3. **Поля потока** (`src/fields.js`) — одна зона, две половины, квадранты, вихрь, полосы.
4. **Отбор и полировка** (`src/generator.js`, `src/polish.js`): из нескольких кандидатов берётся
   ближайший к целям профиля. Потом окна перезаполняются новыми путями, ориентированными по текущему
   порядку снятия, пока метрики приближаются к целям.
5. **Картинки** (`src/shapes.js`, ~25 векторных силуэтов): `mask` — поле в форме фигуры, `fill` —
   фигура выделена цветом стрелок, `contour` — фигура нарисована длинными стрелками-стенами
   (цвет контура 3 или 4, остальные стрелки их не используют).

## Метрики (`src/metrics.js`)

| метрика | смысл | референс ур. 1–3 |
|---|---|---|
| `coverage` | доля занятых клеток | 98,2–98,8% |
| `waves` | длина самой длинной цепочки ожидания | 28–54 |
| `initialFree` | сколько стрелок можно снять на старте | 7–14 |
| `freeMean` | среднее число доступных ходов при игре | 3,6–4,8 |

Чем меньше `freeMean` и больше `waves`, тем больше игроку приходится искать.

## Настройка

- Кривая сложности, размер поля, частота картинок — `src/profile.js` (`DEFAULTS`, `difficulty`).
- Предел поля — `DEFAULTS.maxW / maxH` (32×52).
- После изменения генератора поднимите `GENERATOR_VERSION` в `tools/build.js` и пересоберите с `--force`:
  уровни у игроков должны меняться только вместе с версией.

`reference/` — три уровня референса, снятые со скриншотов, для сравнения метрик.
